## Meta-patterns (why fixes keep failing)

1. **Protections whose failure is silent get discovered failed.** The dominant pattern. `scripts/tests/__init__.py` guards (#256's `DISABLE_LIVE_EMIT`, #412's sandbox, #428's tripwire) were all dead code under `unittest discover` for days-to-weeks; nothing reported "the guard didn't arm." Every fix that finally held added a *loud self-check*: #436's meta-test runs the exact production invocation and fails if the injection is reverted; #428 made the gate treat a clean-summary-nonzero-exit as a synthetic failure; #438(b) made transcript loss alert at creation time. Corollary shipped as doctrine: drift guards (`test_conftest_init_parity.py`, `AllowlistDriftTest`, `test_whitelist_entries_still_exist`).

2. **The protection must attach to the production *invocation*, not to an artifact you hope the invocation touches.** Function-scoped fixtures run after import-time constant freezing (incident 7); conftest only runs under pytest (incident 6); `__init__.py` only runs on package import, which `discover` skips (incidents 5, 7). The fix that held injects env vars into the subprocess — a mechanism "immune to import semantics." Same lesson on the ops side: a merged systemd unit file is not the installed unit file (#438); merged ≠ live.

3. **Enumerate-and-patch fixes leak at the unenumerated member.** PR #53 missed `outbox_notifier` because the grep pattern differed; the env-var override missed every `Path.home()` module; #445 mocks `append_alert` per test file. Each new production write-sink (filesystem → Supabase → alert ledger → bot logs) had to have its own incident before getting its own guard. The constructions that held were *by-construction* fixes: the `zz-fixture-` namespace, the dispatch-boundary gate, the sentinel tripwire (detects *any* escaped write regardless of sink path).

4. **Production code changes are also test-isolation changes.** #438 added one `append_alert` call to a success path and instantly weaponized four pre-existing, previously-harmless test files. No gate asks "does this new production side effect get exercised by existing tests un-mocked?" — the tripwire is the only systemic backstop, and it only instruments `log()`.

5. **Leaked artifacts have a second life.** The 2026-05-28 $261.63 cascade ran on residue from earlier leaks plus a self-replicating routing bug; the TIER_ONE_MARKER lines pooled for days and kept firing false alerts long after the writing stopped (append-only ledgers, no retraction — same property noted for `larry_alerts` in the install-drift memory). Containment fixes therefore always needed a separate manual purge (`~/agents/.fixture-cleanup-20260610`, the 06-02 row count check, the 05-28 hand-drain).

6. **Defense-in-depth was what actually bounded blast radius.** Each layer failed individually, but the consumer-side fixture gate ($0-cost suppression), the `zz-fixture-` namespace, the AST gate, and the tripwire stack so that a single-layer failure now tends to produce noise (false Telegram pages) rather than spend ($261 burns). The cost of the residual failure mode shifted from money to operator attention — which is itself the system's scarcest resource per the alert-toil principle.

# JAIL DESIGN CONSTRAINTS

1. **Same-UID reality: a filesystem-level read-only `/home/larry/agents` is impossible globally.** Production daemons, timers, and tests all run as `larry` on the same box. The jail must be **per-process** (mount namespace / bwrap / fake `HOME`), never chmod/chattr/ACL on the real tree — that would take down all ~50 timers and daemons listed in `systemd/`.
2. **Only a HOME swap (or per-process bind) catches the `Path.home()` class** (H1/H13/H15) — env vars are structurally insufficient. The suite is compatible: tests compare against *dynamic* `Path.home()` (`test_heal_stale_approvals.py:165-173`; `test_log_dir_resolution.py:146` asserts the prod path's **absence**), so they stay green under a fake HOME. H13's import-time `mkdir(exist_ok=True)` calls become harmless jail-local writes.
3. **A fake HOME must not break legitimate HOME readers:** tests that default to `Path.home()/'.claude'/'projects'` (`test_beacon_plan_synthesis_discipline.py:74`, `test_mirror_marker_discipline.py:69`) need `CLAUDE_PROJECTS_ROOT` pinned or an existing empty dir. Git-driving tests are safe — `test_worktree_manager.py`, `test_heal_missions_card_gc.py`, and `tests/scripts/test_push_with_rebase.sh` all set local `user.email/name` — but anything relying on `~/.gitconfig` would break; provide a minimal one in the jail HOME.
4. **Don't blind the tripwire.** Under a fake HOME, `test_no_production_writes_runtime.production_roots()` (`Path.home()/'agents'`, deliberately env-ignoring) scans the *jail* and is vacuously clean forever. The sentinel scan of the REAL tree must run **outside** the jail (parent process, absolute real path), or the jail converts H10's backstop into permanent false-green.
5. **Writes the jail must permit:** `TMPDIR` (mkdtemp in conftest, `__init__`, `build_sandbox_env`, ~every test); the parent repo's `.git` (the gate's `git worktree add/remove` writes `.git/worktrees` metadata — `test_regression_check.py:244-268`); the tmp worktree itself; bytecode (or set `PYTHONDONTWRITEBYTECODE`); and **subprocess exec of python3/git/bash** — the gate IS a subprocess chain and several tests spawn real git, so a no-exec seccomp jail breaks the gate itself. Jail scope must cover `~/agent-worktrees` and `/tmp/wt-main-*` naming, not just `~/agents`.
6. **Env policy must be subtractive, not additive** (fixes M4): strip `SUPABASE_*`, `TELEGRAM_*`, `GH_TOKEN`/`GITHUB_TOKEN`, `ANTHROPIC_*`/`CLAUDE_CODE_OAUTH_*`, and pin `OL_DASHBOARD_API_URL` + pulse-check API URLs to a dead localhost port. Default-deny outbound network is compatible today: no scripts/tests test binds a socket (only string literals, e.g. `test_heal_stale_daemon_code.py:189`), the gate's git ops are local-only, dashboard vitest is in-process jsdom.
7. **If RO-bind of the real tree is chosen instead of HOME swap:** import-time mkdirs survive (`exist_ok=True` over existing dirs), and every unmocked `append_alert`/inbox write becomes a loud `EROFS` test failure — desired fail-loud, but budget for surfacing the latent gaps behind the ~52 mock sites all at once (a wave of "new" failures the regression gate will attribute to whatever PR runs first).
8. **The jail must be runner-anchored AND production-side enforced.** There are now nine-plus invocation shapes across two test trees, two machines, and free-typing agents — they cannot all be patched. Pair (a) one blessed entrypoint that builds the jail with (b) an in-production guard at the choke points (e.g. `larry_alerts.append_alert` and `safe_write_inbox` refusing/diverting when `OURLIBERTY_TEST_RUN_SENTINEL` is set), so a bypassed jail degrades to refusal, not leak.
9. **Never run suites in a live checkout** (fixes M2/M3): drop the `sha == HEAD` in-place fast path; always materialize a disposable worktree and chdir there, so cwd-relative residue can't intersect the auto-commit pathspecs (`PULSE_RUNTIME_PATHS` commits **untracked** files) and a mid-run `checkout main`/ff-pull can't swap the code under the suite.
10. **Budget:** the gate allows 300 s per SHA (`DEFAULT_TIMEOUT_PER_SHA_S`); namespace/HOME-swap setup is negligible, but the bypassed-lock hazard (M7) means any jail that still lets a test reach a real flock sidecar can convert a leak into a gate `AnalysisError` (exit 2) — which Mirror must treat as block, so lock isolation is also a review-throughput requirement.
11. **Cross-machine parity:** the droplet can use bwrap/unshare; macOS cannot — the Mac minimum is the wrapper with fake HOME + subtractive env, plus a one-time purge of the existing `/Users/Larry/agents` phantom tree (M5), which no past cleanup covered.
